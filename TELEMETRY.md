# Performance telemetry — svg-bench-telemetry/1

Every new run writes `telemetry.json`, `telemetry.csv`, section-level `telemetry.json`, and a report table. Existing runs are never rewritten. Timing is grouped by C0 initial creation, C1/C2 enhancement, C3 layout revision; requests also identify section prompts versus tool continuations and returned tool names. These are observable work categories, not inferred hidden reasoning.

- **Client first model delta:** request start to the first nonempty streamed content/reasoning/tool-text delta. Includes transport, queuing and parser buffering. Not necessarily engine TTFT. Chunk arrivals are not token arrivals or exact ITL.
- **Server TTFT, queue, prefill and decode seconds:** runtime measurements, with source and attribution saved per request. Unsupported fields remain unavailable, not zero.
- **Prefill tok/s:** computed, noncached prompt tokens divided by runtime prefill duration. Cached and total prompt tokens are separate. Replay totals are not peak context.
- **Decode tok/s:** runtime-specific numerator and interval. vLLM uses `(generated_tokens - 1) / (last-token time - first-token time)`; llama.cpp uses its `predicted_n / predicted_ms * 1000`. Do not pool these definitions silently.
- **Usage:** prompt, completion and provider-reported reasoning token counts. Reasoning is a subset, not additional output tokens. Report rates use paired observations weighted by engine duration; coverage and request mean/min/max latencies are in JSON.

Direct endpoints stream by default with `stream_options.include_usage=true`. If a provider requires it, a profile can set `stream_usage:false` or `stream:false`; CLI `--no-stream` selects buffered transport. There is no automatic retry that could silently duplicate inference. JSON fallback remains usable but has no first-delta measurement. Limits: 8 MiB request/history, 64 MiB SSE wire data, 2 MiB assembled response. Detailed arrival timing arrays stay in private adapter state, not the 1 MiB JSONL event stream.

Runtime collection defaults to `auto`: bounded, same-origin `/metrics` probes plus per-response llama.cpp `timings` when provided. Use profile `runtime_metrics:"off"` or CLI `--runtime-metrics off` to disable it. No runtime setting is changed. `vllm` explicitly selects the same vLLM collector; auto is best effort, not universal engine instrumentation.

For vLLM shared counters, use an otherwise idle dedicated server. Attribution requires one unambiguous model/engine, idle boundaries, exactly one completion and histogram sample, matching provider token counts, and no observed counter reset. Failure marks engine timings unavailable. These checks still cannot prove exclusivity against perfectly overlapping unrelated traffic. Selected before/after snapshots are saved privately; metrics probe overhead is part of section wall time, not request latency. See [vLLM metrics](https://docs.vllm.ai/en/latest/design/metrics/) and [llama.cpp response timings](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#timings-and-context-usage).

Native Codex/OpenCode and manual runs currently lack request-level engine instrumentation. Their wall times are retained, but TTFT/prefill/decode are explicitly unavailable. Other harness adapters can implement the event contract below. A harness/provider that hides request timing cannot supply full engine telemetry without an integration or instrumented proxy. The launcher does not pretend otherwise.

Adapters emit `adapter.event` with `name:"inference.request.started"`, a unique `request`, `checkpoint`, and `trigger`, then one `telemetry` event with `schema:"svg-bench-telemetry/1"`, matching IDs, `outcome`, `client`, `runtime`, `usage`, and `tool_names`. `client` uses seconds (`duration_seconds`, `time_to_first_model_delta_seconds`); `runtime` uses the named metrics above plus `status`, `source`, `attribution`, `unavailable_reason`, `definitions`, and `decode_token_count` for weighted aggregation. `usage` follows provider Chat Completions counts. Missing values are null/omitted. Emit telemetry before a turn failure; interrupted requests without a terminal record remain identifiable. See the built-in adapter and tests for executable examples.

Raw request/response traces, timing arrays and metrics snapshots can contain private model/system information. Nothing is uploaded automatically. Buffered historical runs cannot be retroactively assigned true TTFT/prefill/decode values.
